# 面试演示脚本（5—8 分钟）

> 目标：让面试官在两分钟内看懂「这不是一个接了大模型的聊天框，而是一套有知识治理和人工兜底的客服系统」。

## 0. 开场（30 秒）

「我做的是一个新能源 4S 店的 AI 客服工作台，解决两件事：常见问题自动答且能给出处，答不了的自动进工单、解决后回写成 FAQ。技术栈是 Python + FastAPI + SQLite，本地一条命令就能跑。」

打开 http://localhost:8000 。

## 1. 看板（1 分钟）

先讲数字，再讲怎么算的：

- 近 30 天 14 个会话、22 条咨询；
- **自动解决率 85%**：AI 建议里被采纳或改后发送的比例；
- **转人工率 13.6%**：投诉、退订、未命中这类必须人工的；
- **FAQ 命中率 86.4%**：置信度达标且带证据的比例；
- **平均首响 9.5 分钟**，满意度 4.0 / 5；
- 右上角「SLA 超时 1」，故意留了一单超时做演示。

如果被问「这些数字是不是编的」：所有数字来自 `messages` 和 `tickets` 两张表实时聚合，点开任意会话能看到每条 AI 建议的状态和置信度。

## 2. 知识库（1 分钟）

- 搜「维保周期」→ 命中「之后多久保养一次」这条，因为同义问法里写了「维保周期」；
- 搜「多少钱」→ 置信度封顶 60%，所以系统会追问车型而不是直接报价；
- 点开一条看字段：分类、适用车型、答案来源、负责人、更新时间、状态。强调「每条知识都有负责人和更新日期，过期的运营能筛出来」；
- 「待审核」的草稿不参与检索——这是知识治理的关键设计。

## 3. 工作台（2 分钟）

按三条路径演示，每条控制在 20 秒：

| 输入 | 预期 | 要讲的话 |
|---|---|---|
| `S7 续航多少` | 直接回答，置信度 93%，带出处 | 答案来自官网参数页，数字可核对 |
| `多少钱` | 追问车型 | 3 字以内的问题置信度被封顶，宁可问一句也不乱报价 |
| `给我个底价` | 转人工 P1 | 价格承诺是硬规则，AI 不许报底价 |
| `我要投诉门店服务态度` | 转人工 P0，首响 15 分钟 | 情绪 + 投诉词命中高风险，直接建单 |

讲决策面板：「这一栏是 AI 的判断过程——意图、车型、情绪、风险原因、命中的三条证据、置信度。客服可以采纳、改完再发、驳回或转人工；客户还能反馈已解决/未解决/答案错误。」

## 4. 工单（1.5 分钟）

- 打开「我要投诉」那一单：P0、首响 15 分钟、已超时红色；
- 演示改状态：处理中 → 已解决，填根因「门店接待态度」、方案「已致歉并安排店长回访」、满意度 4 分；
- 点「生成 FAQ 草稿」→ 提示去知识库审核。

## 5. 回写闭环（1 分钟）

- 知识库出现一条「待审核」，来源写着「工单回写 T-2026…」；
- 点发布 → 状态变「生效」；
- 回工作台再问一遍同样的问题 → 这次直接命中。

收尾一句话：「这条链路就是简历里写的『未命中 → 人工处理 → 根因复盘 → FAQ 回写』，代码在 `tickets.py` 的 `create_faq_draft` 和 `publish_faq`。」

## 6. 飞书多维表格（30 秒，可选）

- 打开表：https://my.feishu.cn/base/NNwtbi7R7a5BBlsFWCjc1WaN6ke ，16 个字段、14 条会话；
- 工作台右上角点「同步到飞书」，选中的会话立刻出现在表里（按「会话ID」去重，不会重复写）；
- 一句话总结：「本地 SQLite 是主存储，飞书多维表格是团队协作层，客服和运营不用进后台就能看会话画像和工单状态。」

如果飞书打不开或网络不通，这一段可以跳过，不影响前面的演示。

## 高频追问与回答

**Q：为什么不用大模型直接答？**
A：价格、保修、退订这些口径不能由模型自由发挥。现在是检索 + 结构化拼接，答案必须带出处；M2 接 DeepSeek 后模型只负责把 Top3 证据改写成客服口吻，并强制校验「答案里的数字必须能在证据里找到」。

**Q：FAQ 多了检索会不会不准？**
A：现在 69 条用 FTS5 + 覆盖度打分足够；上千条会换 pgvector 做向量召回，再做关键词+向量的混合排序。接口层已经隔离，换检索后端不影响业务。

**Q：怎么衡量它有没有变好？**
A：三个指标联动看——命中率上升但驳回率也上升，说明检索把不相关条目排上来了；转人工率下降要配合满意度看，否则可能是硬答。

**Q：为什么还要写飞书？**
A：客服主管不会天天登后台看数据库，他们把多维表格当工作台：会话画像、工单状态、SLA 节点都在表里，还能直接加仪表盘和自动化提醒。系统这边是单向写入，避免两边都能改导致数据打架。

**Q：数据从哪来？**
A：品牌和车型是虚构的，FAQ 是按真实 4S 店话术手工整理的结构化条目，演示会话走的是真实服务链路，不是写死的假数据。

**Q：怎么防止客服改答案改出问题？**
A：修改后发送会留痕（谁改的、改前改后），可以后续加敏感词校验；价格类问题即使客服修改也不允许承诺具体优惠，只能给区间。
