# 工单与 SLA 规则

## 优先级怎么定

| 优先级 | 触发条件 | 典型问题 | 首次响应 | 解决时限 |
|---|---|---|---|---|
| P0 | 投诉；安全类（自燃、刹车失灵、失控、冒烟、事故） | 「我要投诉」「刹车失灵了」 | 15 分钟 | 4 小时 |
| P1 | 退订退款、价格承诺、知识未命中、客户情绪负面 | 「定金能退吗」「给我个底价」「你们股票代码是多少」 | 30 分钟 | 8 小时 |
| P2 | 一般咨询、AI 建议被驳回 | 「保养多少钱」 | 2 小时 | 48 小时 |

规则在 `app/config.py:SLA_RULES` 与 `app/answer.py:_priority`，改优先级会同时改时限，工单表里存的是**建单时算好的绝对时间**，后续改优先级会重算。

## 计时口径

- `created_at`：建单时间（客户消息进入系统的时间）；
- `first_response_at`：工单首次进入「处理中」时打点，或直接置为「已解决」时补打；
- `resolved_at`：「已解决」时打点；
- `sla_first_due` / `sla_resolve_due`：建单时按优先级算出的截止时间，存 UTC+本地时区的 ISO 字符串；
- 未解决且已过截止时间 → `sla.first_response.overdue = true`，看板计入「SLA 超时」。

`GET /api/tickets` 每条工单都带：

```json
"sla": {
  "first_response": {"due": "2026-11-26T03:45:00+08:00", "remaining_minutes": -15, "overdue": true},
  "resolve": {"due": "2026-11-26T07:30:00+08:00", "remaining_minutes": 210, "overdue": false}
}
```

负数就是超时分钟数，前端直接显示红色「超时 15 分钟」。

## 处理闭环

```
待处理 → 处理中（打首次响应）→ 已解决（打解决时间 + 满意度）→ 已关闭
                     └── 已关闭：无需解决（重复单、误报）
```

解决时必须填 **根因分类** 和 **最终解决方案**，否则「生成 FAQ 草稿」会被拒绝（`tickets.create_faq_draft` 抛错），防止空答案污染知识库。

## 知识回写

```
工单已解决 + 有解决方案
  → POST /api/tickets/{id}/faq-draft   生成 FAQ 草稿（状态「待审核」，不参与检索）
  → 内容审核（知识库页面查看，可修改负责人/分类/标签）
  → POST /api/faq/{id}/publish         状态改「生效」，重建 FTS 索引
  → 下次同样问题自动命中
```

草稿的 `source` 字段写成「工单回写 T-20261126-00x」，保证每条 FAQ 都能追溯回是哪一单客户问题沉淀出来的。

## 附录：飞书多维表格字段（已实现，`app/feishu.py`）

会话表（客户资产池）12 列：会话ID、客户昵称、性别、平台、客层、咨询意图、情绪状态、转化状态、标签、询问商品、售价、时间。

工单表 16 列（`python -m app.feishu init-tickets` 创建，`sync` 时按「工单编号」去重写入）：工单编号、用户原始问题、识别意图、车型与场景、AI 召回条目、AI 回答、转人工原因、优先级、负责人、处理状态、首次响应时间、解决时间、根因分类、最终解决方案、用户满意度、是否建议新增 FAQ。
