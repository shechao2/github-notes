# 客服工作流 SOP

> 对象：AI 客服（系统）+ 人工客服 + 内容负责人 + 运营。
> 原则：**AI 能答的答快，答不了的兜住，兜住之后要留下知识。**

## 一、角色与职责

| 角色 | 负责 | 系统里的入口 |
|---|---|---|
| AI 客服 | 检索、回答、追问、低置信度转人工 | 工作台自动完成 |
| 人工客服 | 接工单、回客户、填根因与方案 | 工单页 |
| 内容负责人 | 审核 FAQ 草稿、维护知识库 | 知识库页 |
| 运营 | 看指标、做周复盘、定优先级 | 看板页 |

## 二、状态表（三方统一口径）

**AI 建议状态**（`messages.status`）

| 状态 | 含义 | 后续动作 |
|---|---|---|
| `pending` | 已生成建议，等客服审核 | 客服采纳 / 修改 / 驳回 / 转人工 |
| `accepted` | 采纳并发送 | 计入自动解决 |
| `edited` | 修改后发送 | 计入自动解决，差异进复盘 |
| `rejected` | 驳回 | 自动建工单 |
| `handed_off` | 转人工 | 建工单，按优先级排期 |
| `clarify` | 追问中 | 客户补充后重新走一遍 |
| `no_hit` | 知识未命中 | 建工单 + 进 Bad Case 清单 |

**工单状态**（`tickets.status`）

```
待处理 → 处理中（打首次响应） → 已解决（打解决时间 + 满意度） → 已关闭
```

**FAQ 状态**（`faq.status`）：`待审核 → 生效 → 停用`，待审核不参与检索。

## 三、每日流程（人工客服）

1. 打开**工单页**，按优先级处理：P0 先，P1 次之；
2. P0（投诉、安全）**15 分钟内首次响应**，超时看板标红；
3. 处理完填三样：`根因分类`、`最终解决方案`、`满意度回访分数`；
4. 当天没解决的，状态留在「处理中」，不要直接关单。

## 四、每周流程（运营 + 内容负责人）

1. 看板看四个数：自动解决率、转人工率、FAQ 命中率、平均首响；
2. 打开**Bad Case 清单**，按原因分三类处理：
   - 知识未命中 → 新建 FAQ（草稿）；
   - 客服驳回 / 客户反馈错误 → 修改现有 FAQ 答案；
   - 反复转人工 → 是规则问题还是内容问题，记在周报；
3. 看「Top 10 未命中」补 3—5 条 FAQ，交内容负责人审核；
4. 审核通过后发布，下一周看这条的命中数是否起来。

## 五、知识回写流程（核心闭环）

```
工单已解决 + 已填解决方案
      ↓ 点「生成 FAQ 草稿」
FAQ 草稿（状态：待审核，不参与检索）
      ↓ 内容负责人核对来源与数字
发布（状态：生效，重建检索索引）
      ↓ 下次同样问题
自动命中，命中数 +1
```

规矩：

- **解决不了的工单不建草稿**——系统会拦，避免空答案污染知识库；
- 草稿的 `source` 自动写「工单回写 T-2026…」，任何一条知识都能追到源头客户问题；
- 同一问题一个月内回写两次，说明答案本身有问题，改答案而不是加条目。

## 六、升级规则

| 情况 | 动作 | 时限 |
|---|---|---|
| 命中高风险词（投诉、自燃、刹车失灵、退订、底价） | 立即转人工，AI 不答 | 立即 |
| 客户情绪为负面 | 转人工，优先级 P1 起 | 30 分钟首次响应 |
| 投诉 | P0，值班主管介入 | 15 分钟 |
| 同一客户 24 小时内重复转人工 | 升级到售后主管 | 当天 |

## 七、周报模板（5 行）

```
本周会话 XX 条，自动解决率 XX%，转人工率 XX%，平均首响 XX 分钟，满意度 X.X/5。
Top 未命中：1) XXX  2) XXX  3) XXX
本周新增 FAQ X 条，更新 X 条，待审核 X 条。
SLA 超时 X 单，原因：XXX
下周动作：XXX（补哪类知识 / 改哪类话术 / 调哪个阈值）
```
